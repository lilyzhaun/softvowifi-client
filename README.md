# SoftVoWiFi client

This repository receives versioned App-only source snapshots from the private development repository. It retains the existing drag and liquid refraction UI. The source set includes `app/manager/` (manager and shared code, Gradle wrapper, schemas and tests), `app/observer/src/` and `app/observer/res/` (both compiled by the Android client template), source fixtures, and the listed public country inputs. The standalone unsigned build entry is `bash tools/release/build-apk.sh`; it requires Java 21 and Android SDK Platform 37.0 / Build Tools 36.0.0, but no private source or credentials.

Public country regeneration uses only `tools/export/country_catalog.py`, `tools/export/build_country_catalog.py`, and `export/country-source/{MccTable.java,LICENSE,NOTICE,PROVENANCE.md}`. The public MCC-to-ISO table provides flag lookup, not carrier policy.

Every upstream version release automatically synchronizes this source tree and starts this repository's release workflow. GitHub Releases contain a signed `SoftVoWiFi-v<version>.apk`, the exact upstream `SoftVoWiFi-ksu-v<version>.zip`, `SHA256SUMS`, and public `RELEASE.json` metadata. The client APK is independently built from these sources; it is not claimed to be byte-identical to the APK embedded in the upstream module. Both use the same approved signing certificate and version. Normal source synchronization preserves the separately managed `.github/workflows/` and `tools/release/` control files.

The Git tree does not contain the private VoWiFi engine, OEM/operator data, signing material, private history, or module binaries. The module ZIP is a separately distributed Release asset, not an open engine implementation. A standalone APK without a compatible module cannot provide VoWiFi. The project remains in development: automated builds do not prove complete phone/carrier acceptance or binary redistribution compliance. Repository visibility is not changed by the release workflow.

`LICENSE` contains the unmodified GNU GPL version 3 text for this proposed client-source licensing route. The ten retained KernelSU adaptations remain marked GPL-3.0-only, while the upstream KernelSU manager grants GPL version 3 or later. Other MIT and Apache grants, including earlier MIT snapshots, are not revoked by this proposal. See [NOTICE](NOTICE) and [known issues](KNOWN_ISSUES.md).
